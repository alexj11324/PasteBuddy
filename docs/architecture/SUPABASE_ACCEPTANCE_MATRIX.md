# Supabase migration acceptance matrix and traceability

## Purpose and status

This matrix is the cross-work-package acceptance contract frozen by WP0. Every
row has an owner, a falsifiable check, and required evidence. WP0 only writes
the contract, so every implementation row is **Not run — WP0 documentation
only** until the named work package produces evidence.

**MUST / SHALL** statements are release gates. A source scan, source-token UI
test, static preview, fake transport, or compilation-only result is
intermediate evidence and cannot close a runtime row.

## Evidence rules

For each applicable macOS/iOS row, retain the real environment, build/source
commit, entitlement and privacy state, request/revision IDs where safe, final
UI screenshot, accessibility tree, and relevant runtime frame/geometry. Do not
record clipboard payloads, OCR text, raw keys, tokens, signed transactions, or
pairing material in evidence.

The runtime gate uses the real installed application and the real user path:
build, launch, sign in or remain offline, perform the operation, exercise
failure/retry/expiry as applicable, relaunch, and inspect the final result.
Static source assertions and UI source-token tests cannot replace this loop.

## Release decision rule

No row may be marked Pass because documentation exists. A row is Pass only
when its evidence is attached and reproducible against the exact source
commit/build. Any failed security, entitlement, tombstone, deletion, privacy,
or real-runtime row blocks release. A model bake-off can leave candidate
selection open until all quality and cost gates are recorded.
